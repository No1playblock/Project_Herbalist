# 미로 화면과 수액 포인터 조작

보충물 배치는 사용자 제공 `수액_미로_시스템.pdf`의 1~3쪽 도면을 기준으로 2026-10-26 갱신했다. 노란 테두리·남색 타원의 중심을 실제 미로 홈에 대응시켜 `Refill_+20_N` Transform을 옮겼다. 위쪽에 몰려 있던 배치를 고쳤으며 개수는 1번 4개, 2번 7개, 3번 8개다. 미로 메시, 시작·도착·누수 표식과 수량 설정은 변경하지 않았다. 세 미로의 정면 렌더를 PDF와 대조했고, 저장된 씬을 별도 Preview Scene에서 읽어 19개 모두 +20 획득 및 중복 획득 방지를 확인했다. 도면 좌표와 배치 대조 자료는 `Logs/MazePdfReference`에 있다. 전체 경로 수동 플레이와 Host/Client 실접속 검사는 이번 배치 변경에서 수행하지 않았다.

현재 플레이 씬은 `Assets/_Project/Scenes/Stages/Stage_02/Stage_02_Mazes.unity`다. 앞쪽 수액 역할이 활성 미로의 조작 구역에서 R을 누르면 미로 화면을 열고, 좌클릭을 누른 채 경로를 따라 드래그해 수액을 이동한다. 좌클릭을 놓으면 수액이 멈추며, R을 다시 누르면 캐릭터 조작으로 돌아간다. 현재 세 미로는 `Limit Pointer Path Distance`를 꺼서 먼 목표라는 이유로 이동을 중단하지 않는다. 실제 벽, 누수·보충·재시도와 Host 권한 처리는 유지한다.

## 2026-10-26 수정

일부 `MazeCameraFrame._mazeBounds`가 실제 조작용 `SapMazeSurface.MazeCollider`가 아닌 이전 미로 오브젝트를 참조했다. 첫 미로의 경우 실제 메시 중심은 높이 약 196.78인데 카메라 기준은 약 73.31이어서 수액과 경로가 화면 밖에 있었다. 현재 각 프레임이 해당 보드의 실제 메시를 참조하도록 저장했다.

`SapMazeBoard.TryProjectPointer`는 플레이어 카메라의 해당 viewport 안에서 실제 미로 메시와 클릭 레이를 교차시켜 보드 좌표를 얻는다. 비스듬한 카메라에서 메시 표면과 보드 루트 평면 사이 깊이 때문에 생기는 오차도 줄였다. 메시를 벗어난 포인터는 기존 평면 투영으로 처리하고 경로에 Snap한다. 화면 밖/NaN/무한대 입력은 거부하며, 현재 보드를 조작하는 플레이어의 View만 포인터를 보낼 수 있다. 솔로와 Fusion 입력이 같은 투영 함수를 사용한다.

미로 카메라를 사용 중인 로컬 플레이어에게만 `PlayerHud`의 조준선·도움말 힌트·소지품·능력 안내·피드백과 `GameOverlayHud`의 기존 StageHeader를 SetActive로 숨긴다. 별도 UI를 런타임에 만들지 않는다. 미로 자체의 상태/수액량 표시는 유지하며, R 종료·재시도·완료로 조작이 끝나면 일반 HUD를 복원한다. 다른 네트워크 플레이어의 HUD는 변경하지 않는다.

`Herbalist.Editor.MazePointerViewChecks.Run()`은 새 오프라인 Play 세션에서 실행한다. 원래 진입/운반 과정을 먼저 완료하고 임시 수액량으로 세 미로를 검사한다. 테스트 후 Play를 종료하며 테스트 상태를 씬에 저장하지 않는다. 세 미로의 카메라 참조, 시작/도착 위치의 화면 포함, 화면 클릭 좌표 투영, 실제 능력 Tick을 통한 좌클릭 드래그 이동/버튼 해제 정지, R 진입/종료, 소유자 이동 잠금, HUD 숨김/복원 검사를 통과했다. 이번 수정의 실제 두 프로세스 Host/Client 재검사는 수행하지 않았다.

씬을 복사하거나 미로 메시를 바꿀 때는 보드의 Surface와 연결된 `FrontCamera > MazeCameraFrame > Maze Bounds`가 같은 MeshCollider를 참조하는지 확인한다.

## 좁은 통로와 시작·도착 지정

기존의 가장 깊은 홈만 선택하고 가장 큰 연결 구역만 남기던 판정을 제거했다. 앞쪽 벽 높이와 구분되는 열린 홈을 모두 경로 후보로 사용하며, 보드의 실제 메시를 따라 점 크기의 수액을 이동한다. 깊이가 다른 얕은 연결부나 다른 연결 구역을 임의로 삭제하지 않는다. 인접 표본 사이와 실제 이동 구간도 메시와 충돌 검사하므로 얇은 벽을 건너뛰지는 않는다. 물의 표시 폭은 좁은 통로에 맞춰 줄이며 표시 여백 때문에 폭이 0이 되지 않도록 했다.

현재 세 보드의 `SapMazeSurface > Cell Size`는 보드 로컬 단위 0.04로, 기존 0.1보다 세밀하다. 이 격자는 꺾인 길의 자동 우회 탐색에 사용한다. 직접 드래그하는 구간은 격자에 앞서 실제 메시 선분 검사를 사용하므로, 격자보다 좁은 틈도 물의 중심점이 통과하면 지나간다. 매우 좁은 굽은 길의 자동 우회까지 필요하면 Cell Size를 낮춰 추가 확인한다. `Channel Depth Tolerance`는 벽 앞면의 요철을 통로로 오인하지 않게 하는 깊이 허용값이며, 수액의 반지름이 아니다. 표본 수 상한은 `Maximum Samples`로 관리한다. 변화 없는 메시 판정과 인접 구간 충돌 결과는 캐시하며 경로 탐색 배열은 재사용한다.

시작·도착 지점 변경:

1. Play를 끄고 `StageFour_Layout/SapMaze_1`(또는 2·3)을 선택한다.
2. Inspector 상단의 **시작점 선택 / 도착점 선택** 버튼을 누르거나, `MazeRouteMarkers/StartMarker`, `GoalMarker`를 직접 선택한다.
3. 마커를 원하는 통로 위로 옮기고 씬을 저장한다. 보드를 선택하면 Scene 뷰에서 두 지점의 이동 핸들을 사용할 수 있다. 초록은 시작, 노랑은 도착이다.
4. 다른 Transform을 쓰려면 Inspector의 **시작 마커 / 도착 마커** 참조를 교체한다.

시작·도착 계산은 이 마커를 우선하며 이전 그래프의 고정 시작/도착 번호를 강제하지 않는다. 유효한 통로 위의 좌표는 격자 중심으로 옮기지 않고 그대로 사용한다. 벽 위의 잘못된 지점은 내부 계산에서 가까운 통로로 보정하고 경고하지만, 작성한 마커 Transform 자체는 덮어쓰지 않는다. 마커 변경은 다음 Play 시작 때 적용한다.

`Channel Depth Fraction`은 벽 앞면(0)과 통로 바닥(1) 사이에서 충돌을 검사할 깊이다. 현재 메시의 낮은 벽까지 막도록 기본값 0.5를 사용한다. 메시를 교체할 때 얕은 홈과 낮은 벽을 구분하도록 조정한다. 표시용 수액 폭과는 별개다.

검사: `MazePassageChecks.Run()`에서 폭 0.03의 얕은 연결부와 격자보다 좁은 폭 0.003의 틈 통과, 점 이동, 완전히 막힌 벽과 표본보다 얇은 벽 차단, 격자에 맞지 않는 유효 좌표 보존 및 좁은 물 표시 폭을 확인했다. `MazePointerViewChecks.Run()`에서 실제 세 보드의 경로 연결, 시작/도착 교환이 실제 시뮬레이션에 반영되는 것, 마커 Transform 보존, 먼 목표 이동 및 기존 포인터·HUD 검사를 통과했다. 실제 두 프로세스 Host/Client 재검사는 별도다.

## Scene 뷰와 게임 화면의 미로 음영

씬 조명을 끈 Scene 뷰의 정면 표시를 기준으로 게임 화면을 조정했다. 기존 게임의 옆 방향 보조광과 강한 노멀맵 조합이 나뭇결 요철을 과장했다. Maze1/2/3 재질의 `_NormalScale`은 1에서 0.5로 낮추고, 현재 Stage_02_Mazes의 앞/뒤 보조광은 각각 Y 270/90도, 강도 1/0.75로 맞췄다. 환경광은 Flat 0.18, 주 방향광 강도는 0.35다. 세 MazeCamera 앵커는 X 기울기 8.53도 대신 정면 0도로 맞췄다. 모든 값은 재질/씬에 저장하며 충돌 메시와 경로에는 손대지 않는다. 실제 PlayerCamera 렌더를 확인했고 세 미로의 클릭 투영/수액 이동 회귀 검사를 통과했다.

## 미로 구멍의 잎 덮개

수액량과 도착 목표량은 각 `SapMaze_1~3/MazeVolumeRear` World Space Canvas에 두 줄로 표시한다. 표시 위치는 미로 뒷면에서 바라본 우측 하단이며 밧줄 안쪽에 붙어 미로와 함께 움직인다. 보드의 `_volumeDisplay`가 해당 표시를 참조하고, 활성 미로가 진행 중일 때만 현재 수액량과 목표량을 갱신해 보여준다. 개인 화면에 추가했던 `PlayerHudUI/MazeVolumeBottomRight` 오브젝트와 HUD 참조는 제거했다. 목표는 수집 개수 대신 남은 수액량 기준이다. 현재 설정은 시작 60, 보충물 하나당 +20, 목표 1번 110 / 2·3번 150이므로 누수가 없을 때 보충물 최소 3 / 5 / 5개가 필요하다. 누수로 수액을 잃으면 더 필요할 수 있다.

12개 구멍의 LeafSocket은 뒷면의 갈라진 흔적 중심에 맞추며, 잎의 넓은 면이 미로 판과 평행하도록 회전한다. 모든 덮개는 가장 큰 흔적을 기준으로 동일한 크기(약 가로 14.85, 세로 32.23, 시각 두께 0.12 월드 단위)를 사용한다. `LeafInstallTarget._installedVisualScale`은 이 소켓에 설치된 잎에만 적용되는 시각 Transform 크기다. 0이면 기존 공용 설치 배율을 사용하므로 점프대와 일반 벽의 크기는 변경하지 않는다. 공용 `SO_RevisionLeaf` 배율 자체도 유지했다.

`SapMazeBoard.InitializeSurface`는 경로에 누수 지점을 Snap할 때 작성된 소켓과 타깃 사이 상대 위치를 보존한다. 누수 시뮬레이션 지점은 기존 경로를 유지하고, 덮개는 흔적 중심에 붙는다. 실제 투척으로 12개 모두 설치·판과 평행한 회전·동일 크기·Blocked 판정 및 잎 제거 후 해제를 검사했다. 클라이언트 `ApplyReplica` 경로에서도 12개 타깃의 동일 크기가 적용되는 것을 확인했다. 두 프로세스 Host/Client 실접속 검사는 수행하지 않았다.
