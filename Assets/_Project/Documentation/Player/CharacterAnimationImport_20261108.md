# 캐릭터 애니메이션 및 PF_Player_2 반영

- 원본: `develop_fix__anime`, `375e2eba` (`fix_character`). 사용자 전달의 `develop_fix_anime/fix_character`는 원격 브랜치명과 커밋명을 확인해 이 버전으로 해석했다.
- `PF_Player_2`는 GUID를 유지해 `Assets/_Project/Prefabs/Characters`로 이동했다. 원본에 들어 있는 소담·두영의 본 위치, Spring Bone 및 충돌체 설정을 현재 플레이어 시각 계층에 반영했다.
- 플레이어 루트, 모터, 능력, 네트워크 구성 및 씬 배치는 유지한다. 기존 플레이어 프리팹 5개와 메인 스테이지 3개의 솔로 캐릭터에 적용했다. 2·3스테이지의 누락된 두영 시각 계층과 애니메이션 컴포넌트도 연결했다.
- 두영은 `SO_DuyeongAnimationProfile`의 28개 자세를 사용한다. 이동·점프·착지, 채집 성공·실패, 소지·전달·복용, 능력, 천, 활강 동작을 기존 게임 상태에 연결한다. 소담은 기존 프로필을 유지하며 변경된 손 모션 이름 및 새 제작 성공 클립을 연결했다.
- 두영 받기 모션은 원본 컨트롤러가 제공하는 `pickup_clear`를 사용한다. 문서의 `dy_pickup`이라는 별도 상태는 원본에 없었다. 원본 PF_Player_2가 사용하는 모델은 수정된 `dy_v5`이며, 함께 추가된 `dy_v6`로 임의 교체하지 않았다.
- 누락된 외부 아바타를 참조하던 신규 FBX 17개는 저장된 휴머노이드 매핑으로 자체 아바타를 생성한다. Animator 루트 모션은 계속 비활성화한다.

## 검증

- `ImportedCharacterAnimationChecks.Run`: 새 모델에서 두 캐릭터 총 57개 자세, 상태·레이어·아바타 및 루트 모션 비활성화 확인.
- 기존 `SodamAnimationTimingChecks.Run`, `DuyeongAbilityPresentationChecks.Run` 통과.
- 실제 플레이 모드에서 1·2·3스테이지 로드, 프레임 진행 및 역할별 모델·프로필 활성화 확인. 1스테이지 소유 전환과 2스테이지 소담→두영 전환 확인. 3스테이지 두영 렌더링 점검. 확인 후 Unity Console 오류 0건.
- 두 클라이언트를 연결한 실제 네트워크 플레이는 이번 확인 범위에 포함하지 않았다.

`CharacterAnimationBranchImport`는 아트 프리팹의 시각 설정을 기존 플레이어에 다시 적용하는 Editor 전용 도구다. 프로필의 튜닝 수치는 에셋에서 조정할 수 있다.

## 잎 동작 타이밍 보정

- 서기·활강 자세별 손의 발사 구간을 샘플링해 발사 준비 시간 0.25초에 맞춰 클립 시작 지점을 조정했다. 회수 접촉 구간은 0.3초 예고 시간에 맞춘다.
- 가까운 잎은 실제 남은 비행 시간만큼 받기 타임라인을 앞당긴다. Host의 `CatchElapsed`를 ThrowElapsed와 같은 방식으로 복제하고 늦은 통지의 블렌딩도 남은 시간 안에 끝낸다.
- 두영·소담 모두 점프 하체로 실제 `sodam_lower_jump` 클립을 사용한다. 발사·받기 중 점프와 착지에서도 상체 동작을 유지한다. 두영 하체 마스크에는 골반을 포함해 정지 회수 중 발이 미끄러지지 않도록 한다.
- 프로필 접촉 시점 및 지연 통지 검사, 근거리 회수 시간 검사, 두 캐릭터의 이동·공중·정지 능력 모션 검사를 통과했다. 실제 플레이에서 두 캐릭터의 잎 생성·회수 및 접촉 타임라인을 기록했다.
