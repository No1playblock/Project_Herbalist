# Project development rules

- Follow the supplied game design; clarify ambiguities affecting architecture.
- Before implementing a new feature or changing architecture, explain future extension needs, options and a recommendation in Korean, and obtain the user's choice. The initial separated CharacterController motor architecture is approved.
- Keep tuning values and content in serialized configuration/assets, not gameplay code or key checks.
- UI must use UGUI, authored in the scene/prefab hierarchy before play and shown/hidden with SetActive. Never create UI at runtime.
- Separate input, locomotion backend, abilities, presentation and networking. Minimize changes required to add abilities without speculative frameworks.
- Discuss major architecture changes before proceeding. Photon Fusion with Host (client-server) topology is selected and approved. Fusion SDK 2.1.2 build 2279 is installed; App ID is configured and real Host/Client connection plus two-player scene transition have been verified. Main-menu UGUI and Host/Client session flow with automatic scene transition at two players are approved. Host-authoritative player spawning, local predicted movement and grounded Space jump are approved and implemented. Space is reserved for normal jump; ability keys will be decided later.

- Viewport split/personal switching is approved: Duyeong left, Sodam right; Tab is a rebindable presentation action. Each peer selects its own mode. Keep authored common/character UGUI roots and owner-scoped forced-mode overrides separate from player input/network simulation. Prototype role assignment maps serialized spawn slots to roles.

- Leaf ability architecture approved: component-based unlock/input/leaf gameplay/target reactions/Fusion adapters. R cycles Off -> Pin -> Platform -> Off; left click uses selected mode, immutable per throw. Flying/installed/returning leaves share capacity 3. At capacity recall oldest installed leaf, wait for its return, require another click; no queued auto-throw. Potion unlock is a separate authoritative hook; prototype grants both Duyeong and Sodam for multiplayer testing, plus the offline player.

- Sap ability architecture approved: extract one blob from an explicit interactable SapSource, guide it with mouse aim, and attach/inject with left click; R starts or cancels control. Separate source, control/movement, deposit state, receiver reactions and Fusion replication. Movement/jump lock is owner-scoped while controlling. Configuration/assets hold ranges, speed, lifetime, capacity and binding tolerances. Sap-first positional binding persists until leaf recall; leaf-first sap never retroactively binds. UGUI remains preauthored. Prototype defaults now grant offline/slot 0 Sap and slot 1 Leaf (configurable), superseding the earlier both-leaf test grant; potion choice remains independent of character. Maze movement and full jump-pad/altar mechanics are not part of this initial sap implementation.

- Character presentation uses an authored Sodam model for offline play and spawn slot 1 only. Body yaw follows camera yaw even when stationary or movement-locked; S backpedals and A/D strafe without turning toward movement. Pitch still drives the head. Animation remains presentation-only with root motion disabled.

- Sap flow revision approved (A): separate extraction/hover/flight gameplay, placement preview and fluid-stream presentation. Select the nearest available source surface relative to the player, extract there and hover beside the right side of the face. Maintain the shortest source-surface-to-blob stream while extracting/holding. Click fixes a receiver-local destination and launches the blob, releases movement/jump lock, and draws a launch-origin-to-blob stream until arrival. Placement lifetime begins on arrival; preserve existing binding rules. Preview is preauthored and owner-only; Host owns gameplay and replicates sap state, pose and stream start.

- Temporary test menu approved: MainMenu uses an authored mode-selection panel controlled by PrototypeModeMenu. Solo directly loads the configured play scene; Multiplayer reveals the existing LobbyCard. When asked to remove solo play later, follow Assets/PlayerPrototype/PrototypeModeMenu.md: remove the temporary menu root/script and BackToModeSelection, activate LobbyCard by default, preserve existing Photon room UI and direct offline Editor testing unless explicitly asked otherwise.

- Stage One gathering/crafting/drinking architecture approved: serialized item and recipe assets, one held item, Duyeong-only gathering and camera-specific herb glow, Sodam-only immediate prototype crafting, nearby direct transfer, separate drinking input, and permanent one-potion ability choice independent of character. Host validates all actions and replicates progress; both distinct potions must be made and consumed before the entrance opens, and both players must be inside for clear. StageOnePrototype is the multiplayer test destination; original PlayerMovementPrototype remains the solo ability sandbox. See Assets/StageOne/README.md.

- Separate exterior/interior stages approved: Sacred_Tree is Stage One exterior/real entrance; StageTwoPrototype starts centrally within six playable Root_Big_Final trees. Host snapshots player slot and consumed ability across Fusion scene loads, with no character-fixed reassignment. Stage Two has a persistent catch floor, player-built intermediate leaves and a shared upper arrival goal; do not reset ability objects on falls. See Assets/StageTwo/README.md.

- Camera/control trial approved: PlayerTuning.facingMode = MovementDirection. Camera orbits independently; camera-relative WASD turns body toward movement with bodyTurnSpeed. Idle/locked body holds heading. Solo and Fusion use the same resolver; BodyYaw is networked. To roll back to the previous camera-aligned strafe/backpedal controls, set Assets/PlayerPrototype/PlayerTuning.asset Facing Mode to CameraAligned; no code rollback required. Keep camera height, pitch limits and animation damping unchanged.

- Ability hose trial approved (A): preserve Placement mode; enable Hose in SapAbilitySettings. Hold Use to spray from body-relative right chest, without source stream or placement preview. Allow empty-space shots and grow nearby same-surface marks, expiring 5 seconds after the last hit only while unbound. Once sap and leaf bind, both persist without timeout until leaf recall/removal, which also removes the bound sap. Leaf accepted throws face aim. Host owns hits/growth/lifetime. Rollback switches and verification: Assets/PlayerPrototype/AbilityHoseTrial.md.

- Shared game UI architecture A approved: preauthored MainMenuUI, OptionsPanel, LoadingPanel, GameOverlayUI and PlayerHudUI prefabs. Distinct character selection replaces automatic two-player start; Host starts when both roles are selected. RoomControl validates selection and shared pause via Fusion reliable messages. The requesting peer owns resume; transport remains active while gameplay pauses. Esc pause, H key help, existing Tab split/personal. Solo test entry removal now follows the updated Assets/PlayerPrototype/PrototypeModeMenu.md. See Assets/GameUI/README.md.
