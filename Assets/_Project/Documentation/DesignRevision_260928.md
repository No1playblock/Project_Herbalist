# 260928 기획 개편 검토

상태: 사용자의 진행 승인에 따라 A안 구현. 세 씬 구성, R 대상별 능력 사용, 내부 하강 끝의 제단을 적용했다. 프로토타입 배치이며 최종 아트/연출은 별도 제작 대상이다.

기준: `서낭당_레벨_기획서_260928.pdf` (35쪽). 문서에 남아 있는 이전 스테이지 번호와 상향 진행 설명은 최신 하향 진행 설명과 구분한다.

## 추천 구성

기존 기능을 재사용하고 진행 흐름은 세 씬으로 분리한다.

1. 외부: 약초 채집·제조·복용 → 무당나무 외벽 상승 → 두 명 상단 도착 → 수액 주입으로 입구 개방 → 두 명 내부 진입.
2. 미로: 각자 뗏목에 진입 → 같은 두 뗏목으로 세 미로를 차례로 하강 → 마지막 미로 완료 시 다음 씬 이동.
3. 제단: 수액으로 석판 회전 → 나뭇잎으로 각도 고정 → 문양 정렬 → 계단 변형 → 두 명 탈출.

## 구현 및 실행

- 로비 시작: `Assets/_Project/Scenes/Stages/Stage_01/Stage_01_Exterior_260928.unity`
- 미로: `Assets/_Project/Scenes/Stages/Stage_02/Stage_02_Mazes.unity`
- 제단: `Assets/_Project/Scenes/Stages/Stage_03/Stage_03_Altar.unity`
- 새 설정: `Assets/_Project/Data/Stages/Revision_260928/SO_StageAbilityRules.asset`. 나뭇잎/수액/UGUI 설정은 기존 에셋의 복사본을 사용한다.
- 이전 스테이지 씬은 2026-09-30 정리에서 제거했다. Sandbox_Abilities는 솔로 능력 테스트용으로 유지한다.

R을 누르면 단일 나뭇잎을 던진다. 벽에서는 긴 축의 끝을 얕게 박고 조준 방향을 유지하며, 점프대·누수 구멍·제단 소켓에서는 대상이 지정한 위치와 방향에 설치한다. 고정/발판 모드는 없다. 좌클릭은 가장 오래된 설치 나뭇잎 회수다. 설치 수명은 없으며 네 번째 투척은 오래된 설치물을 회수하면서 즉시 새 투척을 시작한다. 비행 중인 나뭇잎은 설치 슬롯을 예약하므로 동시에 과도한 투척으로 한도를 초과하지 않는다. 물은 파란색이며 나뭇잎과 결합하지 않는다. 물의 소멸과 나뭇잎 회수는 서로 영향을 주지 않는다.

수액은 나무에서 추출하지 않고, 주입 가능한 기믹을 조준해 R을 누르는 동안 생성·주입한다. 미로 앞 조종 영역에서는 R이 조종 시작/종료로 동작하고 WASD가 수액을 이동시킨다. 입력은 기존 InputActionReference를 유지하므로 바인딩을 변경할 수 있다.

외부는 PDF 20~23쪽의 한 나무를 여러 방향에서 본 도면을 기준으로 다시 배치했다. 노란 점프대 가지 4개, 주황 일반 가지 3개, 파란 천 3개와 초록 나뭇잎 다리 구간 4개가 있다. 파란색은 사용자의 색상 설명을 따른다. 기존 네 방향 반복 경로를 제거했다. 초록 구간에는 나뭇잎을 붙일 수 있는 수직 벽만 있으며 고정 다리 바닥이나 사전 설치 나뭇잎은 없다. 플레이어가 설치와 회수를 반복해 올라간다. 두 약초는 나무의 서로 다른 쪽에 있으며 시작점, 솔로 물약과 멀티 스폰도 새 경로에 맞췄다.

점프대는 반대 구멍으로 3초 주입 후 분출하며, 나뭇잎 위에 서 있던 플레이어에게 분수대의 상승 속도를 더한다. 상승 중에도 WASD로 이동할 수 있다. 최고점에서는 상승력을 없애고 위쪽 발사 속도 없이 일반 중력 낙하로 전환한다. 낙하 중에도 WASD로 착지 방향을 결정한다. Space는 일반 점프만 담당한다. 반대 구멍에 나뭇잎이 없어도 분출한다. 상승 칼럼 위의 나무/최상층 바닥/입구 지붕이 겹치지 않도록 가지와 상단 입구를 배치했다.

도면에는 미터 단위 치수가 없으므로 현재 Sacred_Tree 크기에 맞춘 블록아웃이다. 가지 높이는 6/8/16/21/25/30/35m이며 천 매듭은 8/21/31m다. 높이 순서와 연결 방식은 도면을 따르고, 각도와 간격은 실제 나무 충돌 및 도달 거리에 맞춰 조정했다. 설정은 `SO_ExteriorLayout_260928.asset`의 branches/cloths/leafBridges/spawnOffsets/herbOffsets에서 바꾼 뒤 `Herbalist/Stages/Apply PDF Exterior Pages 20-23` 메뉴로 현재 외부 씬에 반영한다. 메뉴는 Edit 모드에서만 동작하고 런타임 UI를 만들지 않는다. 최초값은 에디터 빌더에서 생성하고 이후 저장된 설정 에셋을 사용한다. 전체 등반 난이도는 두 명의 실제 플레이로 추가 조정해야 한다.

천은 매듭 근처에서 E로 잡고 놓는다. 두 명이 매달릴 수 있으며 먼저 잡은 플레이어가 카메라 기준 WASD로 흔든다. 최초 조종자가 놓으면 남은 탑승자가 조종한다. 흔들림은 최대 30도, 복귀·감쇠·장애물 검사 설정을 가진다. 천과 나뭇잎은 체크포인트가 아니다. 큰 낙하가 감지되면 해당 슬롯의 마지막 일반 발판 착지 위치로만 복구한다.

외부의 중앙 상단 입구는 두 약제 제조/복용, 두 명 상단 도착, 수액 주입을 모두 요구한다. 두 명이 열린 입구 내부에 들어가면 미로로 전환하고 캐릭터 슬롯과 복용 능력을 보존한다.

미로는 같은 두 뗏목을 계속 사용한다. 시작 낙하 카메라 이후 첫 보드로 내려가며, 각 미로 해결 시 자동 하강한다. 세 번째 해결 직후 제단으로 전환한다. 개인 화면이 강제로 유지되고 Tab 전환이 잠긴다. 앞쪽 도면에서 누수 표시는 제거하고, 앞/뒤 전용 레이어 및 카메라 마스크로 다른 쪽 정보가 보이지 않게 한다. 도면/그래프는 기존 PDF 추출 데이터를 재사용한다. 새 3배 키 사거리에서 누수 구멍에 도달하도록 보드의 월드 크기와 뗏목 거리를 조정했다.

제단의 상단 석판은 고정이며 세 하단 석판은 서로 다른 속도/방향으로 회전한다. 나뭇잎은 틀린 각도에서도 멈추게 하며, 회수하면 다시 돈다. 세 석판을 목표 각도에 고정하면 계단 위치로 변형된다. 두 플레이어가 밖의 출구에 도착하면 미리 배치한 UGUI 클리어 패널이 표시된다. 사신 문양은 현재 방향/이름 텍스트로 대체한 프로토타입이다.

## 구조 및 조정

20~23쪽 재배치 검증: 씬의 참조/고유 나뭇잎 ID/사전 배치 UGUI와 외부 기믹 검사를 통과했다. 모든 점프대 두 구멍 위 15.5m 운반 경로를 플레이어 크기의 SphereCast로 검사해 막는 비트리거 콜라이더가 없음을 확인했다. CharacterController 시뮬레이션으로 첫 점프대→두 번째 가지 착지, 두 번째/세 번째 점프대→중간/상단 매듭의 E 범위 진입을 확인했다. 중간 천을 흔들고 놓아 일반 가지에 착지했으며 상단 천도 다음 가지의 접근 범위에 도달한다. 상단 천에서 놓았을 때는 원본 Sacred_Tree의 가지 표면에도 착지한다. 천의 카메라 기준 WASD 흔들기 방향이 반대였던 문제를 수정했고, 재발 검사를 추가했다. 이 검증은 두 명이 시작부터 정상까지 전체 경로를 직접 플레이한 결과는 아니다. 새 배치는 기존 개발 빌드에 아직 포함되지 않았다.

- `ExteriorJumpPad`: 두 포트/두 소켓, 주입량, 분출 및 탑승 운반. `SO_ExteriorJumpPad`의 chargeUnits, presentationRise, eruptionRiseDuration, flightDuration으로 조정한다.
  - 나뭇잎은 구멍 부모의 스케일과 무관한 월드 높이로 솟는다. `eruptionRiseDuration`(현재 1.25초) 동안 위로 갈수록 감속해 `presentationRise`(현재 14m)의 최고점에 도달한다. 수액 기둥도 같은 높이로 뻗고, 최고점 이후에는 정지 상태에서 점차 빨라지며 함께 내려온다. 전체 분출 시간 `flightDuration`은 현재 2.5초다. Host가 분출 시작 시 탑승자를 판정하고 상승 속도를 플레이어 모터에 전달한다. 플레이어는 상승과 하강 모두 WASD로 이동한다. 최고점에서는 상승 속도를 해제하고 일반 중력으로 전환한다. 중력과 공중 가속은 PlayerTuning을 사용한다. `jumpWindow`, `jumpReach`, `launchHeightMultiplier`는 새 ExteriorJumpPad에서는 사용하지 않는다.
- `HangingCloth`: 매듭·천 외형·범위·진자 운동·탑승자. Host가 실제 탑승·충돌을 검증한다.
- `LandingCheckpoint` / `ExteriorStageFlow`: 일반 표면 착지와 슬롯별 복구, 상단 도착/주입. 복구는 설치물을 지우지 않는다.
- `DescendingMazeFlow`: 두 뗏목과 정차 높이 배열, 진입/하강/미로/완료. 기존 `SapMazeBoard`가 입력·누수·현재 미로 재시도를 담당한다.
- `AltarRing` / `RotatingAltar` / `FinalStageExit`: 석판별 속도·목표 각도·허용 오차·계단 목적지와 전체 진행 조건.
- `StageTransition`: 기존 Fusion Host 스냅샷 전환을 사용하며, 직접 오프라인 전환은 해당 한 번의 능력 선택만 전달한다.
- 기존 CharacterController 자동 착지점 발사는 유지한다. 새 점프대/천에서만 ExternalAirControl 예측 상태를 사용한다.

UI는 기존 UGUI 계층 및 에디터 빌더로 사전 배치했다. 런타임에는 생성하지 않는다. 키 도움말과 능력 안내는 새 UI 설정 복사본을 사용한다.

## 테스트 및 제한

`DesignRevisionChecks.Authored`, `Exterior`, `Maze`, `Altar`로 에셋/씬 참조, 사거리/교체, 개별 점프·공중 조작, 수액 생성, 두 명 천 잡기, R 미로 조종, 동일 뗏목 하강, 제단 고정/회수/정렬/탈출을 검증한다. 재생 모드 검증의 파트너는 검증 함수에서만 생성하며 일반 플레이에는 생성되지 않는다.

개발 빌드의 명시적 `-herbalist-revision-check host|client 방이름` 옵션으로 두 프로세스 Host/Client 검사도 실행할 수 있다. 그래프 이동은 별도 테스트에서 확인하고 이 연결 검사에서는 미로 완료 상태를 가속해 씬 전환을 확인한다. 일반 실행과 릴리즈에서는 자동 검사하지 않는다.

2026-09-29 검증 결과: `Authored`, `Exterior`, `Maze`, `Altar` 검사 모두 통과. Windows 개발 빌드(메인 메뉴와 새 세 씬)는 빌드 오류 0개로 완료했다. 실제 Photon Host/Client 두 프로세스에서 채집·전달·제조·복용, 상단 주입/진입, 능력 보존 씬 전환, Client R/WASD 조종, 동일 뗏목 자동 하강, 제단 회전 복제를 양쪽 PASS 로그로 확인했다. 경로 이동과 최종 협동 출구 조건은 별도 재생 모드 검사로 확인했으며, 실제 사람이 전체 등반 경로를 플레이한 검사는 아니다. 로그는 무시된 빌드 폴더의 `build/RevisionNetworkCheck/host4.log`, `client4.log`에 있다. Client를 실행하기 전에 Host의 방 생성 완료를 확인해야 한다.

Fusion의 Client 씬 오브젝트 등록 중 비활성화/재활성화에도 개인 화면 강제 설정이 유지되도록 `DescendingMazeFlow.OnEnable`과 `Spawned`에서 소유한 화면 설정을 적용한다. 앞쪽의 누수 표시 제거 텍스처는 GUID를 유지하여 `Assets/_Project/Art/Environments/Stage_02/Textures/Revision_260928`에 배치했다.

미로 직접 실행은 Editor/Development에서 한 명으로도 진입·뗏목 이동을 테스트할 수 있다. Q 테스트 능력 전환을 사용하면 해당 능력 쪽 뗏목으로 옮겨진다. 실제 Photon 세션과 릴리즈는 두 명을 요구한다. 외부 채집/제단 최종 탈출의 협동 조건은 유지한다.

기획의 제단 절에 남은 이전 5스테이지/최상층 표현은 승인된 A안에 따라 하강 끝의 3스테이지로 해석했다. 미로 두 번째 도면에 고립되어 도달하지 못하는 누수 한 개는 원본과 같으므로 그대로 보존했다. 외부/제단 외형과 낙하/나무 발광은 동작을 확인하는 대체 표현이며 최종 연출이 아니다.

## 이전 진행으로 복원

### 외부 솔로 테스트 물약

`Stage_01_Exterior_260928`의 `SoloTest_Potions` 아래에 나뭇잎/수액 물약 프리팹을 시작 위치 앞에 배치했다. 가까이에서 Interact(기본 E)로 집고 Drink(기본 G)로 복용한다. 기존 아이템 카탈로그, 손에 든 아이템 상태 및 한 번만 복용하는 해금 규칙을 그대로 사용한다. 다른 물약을 테스트하려면 Play를 다시 시작한다. 안내는 미리 배치한 UGUI에서 입력 바인딩을 읽어 표시한다.

`SoloPotionPickup`은 Editor/Development 오프라인에서만 동작하며 Photon 세션과 릴리즈에서는 물약 오브젝트를 숨긴다. 제조/두 명 입장 조건을 우회하지 않는다. 임시 물약을 제거하려면 `SoloTest_Potions` 루트를 삭제/비활성화하면 된다. 재사용 프리팹은 `Assets/_Project/Prefabs/InteractiveObjects/SoloTests`에 있다.

솔로에서 물약 선택 없이 두 능력을 시험하려면 **T**(`Player/OfflineUnlockBoth`)를 누른다. 그 뒤 **Q**(`OfflineAbilitySwitch`)로 나뭇잎/수액을 전환하며 R은 선택한 능력 사용으로 유지된다. 1스테이지에서도 T로 해금한 경우 Q 전환을 허용한다. 입력은 `OfflineAbilitySwitcher`의 직렬화 참조이며 H 도움말에 표시된다. 이 임시 해금 상태는 오프라인 씬 전환 시 보존하고 새 Play에서는 초기화한다. Photon 플레이어와 릴리즈에서 T 해금은 거부된다. 제조 기록이나 협동 입장 조건은 우회하지 않는다.

이전 스테이지와 물 Placement 분기는 2026-09-30 정리에서 삭제했다. 복원이 필요하면 변경 전 Git 이력 또는 `Temp/LegacyCleanupBackup_20260930.zip`, `Temp/LegacyCodeBackup_20260930.zip`을 사용한다. 입력 액션 이름과 GUID는 유지했다.

입력, CharacterController 이동, 능력, 표현, Fusion 어댑터 분리는 유지한다. 천·점프대·상단 입구·제단은 배치 가능한 독립 컴포넌트로 만들고, 씬 진행 담당자는 완료 상태만 조합한다. 이후 기믹 배치나 난이도 변경은 설정 에셋과 인스펙터로 처리한다.

미로 도면 세 개는 기존 도면과 이미지가 동일하다. 도면/그래프 데이터는 재사용하고 진행·카메라·뗏목을 변경한다.

## 선택 항목

- 씬: A = 세 씬 분리 및 기존 기능 재사용 (추천), B = 한 씬에서 구간 활성화.
- 입력: A = R을 대상별 능력 사용으로 통일하고 나뭇잎 형태는 대상이 결정 (추천), B = 기존 R 모드 전환/좌클릭 사용 유지.
- 제단: A = 내부 하강 끝의 3스테이지 (추천), B = 별도 상승 경로를 유지해 최상층 배치. 전체 흐름과 제단 절의 예전 설명이 충돌하므로 선택이 필요하다.

## 승인 후 구현 순서

1. 선택된 진행/입력 규칙을 설정 에셋과 문서에 반영한다. 기존 씬·데이터는 개편 검증 전 보존한다.
2. 나뭇잎 대상 판정·거리·수명·한도 교체, 외부 수액 주입과 점프대를 수정한다.
3. 천 잡기/흔들기와 착지 체크포인트를 구현하고 외부 상승 경로를 구성한다.
4. 상단 주입/입구와 능력·역할을 보존하는 씬 전환을 연결한다.
5. 동일한 두 뗏목의 자동 하강, 개인 화면 제한, 미로별 재시도를 적용한다.
6. 회전 제단·각도 정지·정렬·계단 변형·협동 탈출을 구현한다.
7. 사전 배치 UGUI 안내·자막을 연결하고 솔로 디버그와 Fusion Host/Client를 검증한다.

## 검증 기준

- 약제는 캐릭터와 독립적으로 한 번만 선택되며 씬 이동 후 보존된다.
- 사거리 밖 나뭇잎 사용은 개수/상태를 소비하지 않는다. 네 번째 설치 교체는 Host/Client 모두 같은 오래된 나뭇잎을 회수한다.
- 점프대 두 구멍 모두 역할을 바꿔 사용할 수 있고, 빈 반대 구멍에도 수액 분출이 표현된다. 공중 이동은 각 플레이어 입력을 따른다.
- 천의 최초 조종자, 동승/해제, 장애물 충돌이 Host에서 검증되고 복제된다.
- 개인 낙하가 상대 진행이나 설치물을 초기화하지 않는다.
- 외부 입구는 상단 도착/주입/두 명 진입의 조건을 순서대로 검증한다.
- 미로 조종 중 플레이어 이동은 잠기고, 개인 화면 제한은 해당 씬에서만 적용된다. 실패 시 현재 미로만 복구한다.
- 뗏목이 세 미로 사이에서 유지되고 세 번째 해결 후 중복 없이 전환한다.
- 제단의 잘못된 각도 고정도 가능하며 회수 시 회전이 재개된다. 올바른 정렬만 계단 변형을 시작한다.
- 모든 UGUI가 재생 전에 씬/프리팹에 존재하며 런타임 생성 코드가 없다.
